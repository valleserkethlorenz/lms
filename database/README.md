# Database — deployment guide

Everything you need to stand the LMS database up on a new machine, in order.

```
database/
├── README.md                  ← this file
├── DATA_DICTIONARY.txt        ← table/column reference (ERD notes)
├── install/                   ← RUN THESE on a new server
│   ├── 00_create_database.sql
│   ├── 01_schema.sql          (generated: 31 tables, no data)
│   ├── 02_seed_reference.sql  (generated: sports, divisions, venues, doc types, categories)
│   └── 03_verify.sql          (read-only checks)
├── migrations/                ← upgrade path for an existing DB only (001 → 037)
│   └── README.md              (manifest + one-shot warnings)
├── backups/                   ← dumps / snapshots — never part of a deployment
└── archive/
    └── lms_base_dump_2026-05-27.sql   (obsolete 6-table dump — DO NOT USE)
```

## 0. Prerequisites

| Requirement | Minimum | Notes |
|---|---|---|
| MariaDB / MySQL | MariaDB **10.4** (or MySQL 8) | dev uses `10.4.32-MariaDB` |
| PHP | **8.1** | dev uses 8.2.12 |
| PHP extension | `mysqli` | also `mbstring`, `fileinfo`, `curl`, `dom`, `openssl` |

Connection settings live in **`lms/config/dbconnect.php`**
(`localhost` / `root` / empty password / database `lms` in development).
Change that file — not the SQL — for a real server.

## 1. Path A — brand-new install (normal deployment)

```bash
mysql -u root -p < install/00_create_database.sql
mysql -u root -p lms < install/01_schema.sql
mysql -u root -p lms < install/02_seed_reference.sql
mysql -u root -p lms < install/03_verify.sql      # compare with "expected" comments
```

Windows / XAMPP (root has no password by default):

```powershell
& "C:\xampp\mysql\bin\mysql.exe" -u root < install\00_create_database.sql
& "C:\xampp\mysql\bin\mysql.exe" -u root lms < install\01_schema.sql
& "C:\xampp\mysql\bin\mysql.exe" -u root lms < install\02_seed_reference.sql
& "C:\xampp\mysql\bin\mysql.exe" -u root lms < install\03_verify.sql
```

phpMyAdmin: create database `lms` (utf8mb4_general_ci) → *Import* → `01_schema.sql`
→ *Import* → `02_seed_reference.sql`. (`00` only creates the database, `03` is checks.)

Every file starts with `USE \`lms\`;`, so it also works without pre-selecting the database.
If your deployment uses a different database name, either change that line in
each file or import with the database selected on the command line and strip
the `USE` line. (The app reads the name from `config/dbconnect.php`.)

Result: full schema + reference data, **no user accounts**. Create the first
admin with step 4.

## 2. Path B — restore an existing dump (keep real data)

```bash
mysql -u root -p < install/00_create_database.sql
mysql -u root -p lms < backups/<your_dump>.sql
```

Then apply **only the migrations newer than that dump** (see
`migrations/README.md` for dates). Example — restoring
`backups/before_format_removal_20261020_004224.sql` (2026-10-20) needs
`037`, plus `027` and `033` because that dump predates the security tables.

## 3. Path C — upgrade a database that is already in use

Take a dump first, then apply the missing numbered files in order:

```bash
mysqldump -u root -p lms > backups/before_upgrade_$(date +%Y%m%d).sql
mysql -u root -p lms < migrations/0NN_<name>.sql
```

⚠ Never re-run a file marked **one-shot** in `migrations/README.md` — several
use bare `ALTER TABLE ... ADD COLUMN` / `DROP COLUMN` and will error.

## 4. Create the first administrator

The app has no installer wizard. Insert the account with a hash generated by PHP:

```powershell
# 1. generate a bcrypt hash (password policy: 12+ chars, upper, lower, digit, symbol)
C:\xampp\php\php.exe -r "echo password_hash('ChangeMe!2026', PASSWORD_DEFAULT), PHP_EOL;"
```

```sql
-- 2. insert the admin (role 3 = Admin, stat 1 = active, pass_stat 0 = must change password)
INSERT INTO tbl_user (res_id, fname, lname, mname, suffix, phone, email, pass, role, stat, pass_stat)
VALUES ('', 'System', 'Administrator', '', '', NULL, 'admin@lms.com',
        '<paste-the-hash-here>', '3', '1', 0);
```

Roles: `1` Organizer · `2` Team Representative · `3` Admin · `4` Committee.

## 5. Reference data (what lives in `tbl_utility`, not in code)

| Category | Seed rows | Notes |
|---|---|---|
| `sport` | Basketball (5–15), Takraw (3–3), Volleyball (12–14 + sets/scoring), Soccer (11–22), Mobile Legends (5–6), Badminton (1–2), Pickleball (1–2), DOTA (5–6) | roster defaults + volleyball set config live here |
| `division` | Junior (9–12), Under 18 (13–17), Open (16–50), Under 21 (13–20) | age ranges |
| `venue` | 2 rows | free text can also be typed per league |
| `document_type` | Birth Certificate, Medical, Valid ID — scope `player` | requirements attached per league |
| `category` | Male, Female, Mixed | team category |

Operators should extend these through **Admin → Utilities**, not by editing SQL.
The legacy `league_format` category was deleted by migration `037`.

## 6. Verification checklist after any deployment

1. `03_verify.sql` → `table_count = 31`, `missing_table` returns **0 rows**
2. `tbl_league` has `publication_status` and **no** `format` / `format_code`
3. Reference data: 8 sports / 4 divisions / 2 venues / 3 document types / 3 categories
4. `tbl_user` has at least one `role = 3` with `stat = 1`
5. Open `login.php` → page renders, admin can log in
6. `lms/logs/php_errors.log` shows no `Unknown database` / `Unknown column`

## 7. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `Unknown database 'lms'` | database not created | run `install/00_create_database.sql` |
| `Unknown column 'publication_status'` | old `lms.sql` imported without migrations | rebuild with `install/01_schema.sql` (see `archive/`) |
| `Access denied for user 'root'` | server has a root password | edit `config/dbconnect.php` |
| `Cannot add foreign key constraint` | table order / partial import | import `01_schema.sql` into an empty database |
| `Duplicate key name` / `Duplicate column` | a one-shot migration was re-run | restore the dump, re-apply only missing files |

## 8. Regenerating the install files

`01_schema.sql` and `02_seed_reference.sql` are generated — never hand-edit them.
After applying a new migration, refresh them:

```powershell
& "C:\xampp\mysql\bin\mysqldump.exe" -u root --no-data --routines --triggers `
    --skip-add-drop-table --skip-comments lms > install\01_schema.sql

& "C:\xampp\mysql\bin\mysqldump.exe" -u root --no-create-info --complete-insert `
    --skip-comments --where="category <> 'league_format'" lms tbl_utility > install\02_seed_reference.sql
```

Then re-add the header block at the top of each file and re-run
`install/03_verify.sql`.
